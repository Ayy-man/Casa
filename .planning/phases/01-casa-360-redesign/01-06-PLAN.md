<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user free-text input -> Assistant conversation | The Assistant text input accepts arbitrary user-typed strings rendered back into chat bubbles |
| client role -> Assistant greeting/prompts | `useRole()` selects which greeting + canned content renders |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-15 | Tampering / XSS | Assistant rendering user-typed input back into a `.bubble.us` bubble | mitigate | The user's typed message renders as a plain React text child of the bubble `<div>` — React escapes it. The executor MUST NOT use `dangerouslySetInnerHTML` for the user bubble or the canned-response bubble. No network, no eval, no `innerHTML`. |
| T-01-16 | Denial of Service | the canned-response `setTimeout` timers | mitigate | Timers are tracked in a `useRef` and cleared in a `useEffect` cleanup (the preserved `page.tsx:216-239` pattern) — no unbounded timer accumulation across re-renders or unmount. |
| T-01-17 | Information Disclosure | role-aware canned responses | accept | Canned responses are author-written static mock strings (L1 — no real data, no real LLM). Both roles are full admins in Phase 1; no sensitive data is gated or leaked. |
</threat_model>
