## Resolved Tensions

The brief introduces three values that conflict with the existing binding Casa system.
Each is resolved here with one authoritative value.

### Tension 1 — Body font size (brief 16px vs. existing 13px)

**Resolved: 15px base for narrative/reading body; existing 13px retained for dense UI chrome.**

The brief wants a more editorial, readable Exception Board ("bump body to 16px base").
The existing system uses 13px as the default UI body and 14px for `Body Large` reading
prose. Jumping the whole app to 16px would visually re-skin every preserved surface
(Pricing Agent detail, tables, sheets) — out of scope for a structural refactor and a
violation of "Keep unchanged → existing fonts and brand-font decisions."

Resolution: introduce a **15px reading-body tier** (`text-[15px]`, line-height 1.55)
used for exception-card narrative bodies, the Assistant conversation, and Vault
key/value detail prose. **Keep 13px** (`text-[13px]`) for table cells, pills, nav
links, sheet metadata, and all preserved-surface chrome. This honors the brief's
intent (the reading surfaces feel more editorial) without re-skinning the whole app.
15px is the single new size; the typography table below declares the full 4-tier set.

### Tension 2 — Route background (brief `#FAFAF7` vs. existing `#FFFFFF`)

**Resolved: `#FAFAF7` for the route canvas (Tier 0); cards stay `#FFFFFF`.**

The brief asks for an off-white canvas "softer than pure white" so white cards lift off
it. The existing system already sanctions barely-off-white surfaces (`surface-soft`
`#FAFAFA`, `surface-quiet` `#FCFBF9`) and explicitly forbids only `#FFF`/`#000` — not
soft tints. `#FAFAF7` is within that family. Apply `#FAFAF7` as the `body`/route
background; **keep all cards, sheets, and panels pure `#FFFFFF`** with the existing 1px
`#E5E5E5` rule. This makes the white exception cards read as lifted Tier-1 surfaces
against a quiet canvas — consistent with the Flat-at-Rest Rule (the lift comes from the
canvas contrast + border, not from a resting shadow).

### Tension 3 — "PINNED FOR {ROLE}" green (brief green vs. Casa blue One Voice Rule)

**Resolved: pin highlight uses Casa blue `#1E5FBF`, not green.**

The brief's Vault section says role-pinned cards get a "green border + 'PINNED FOR
{ROLE}' badge." Green is a status color in Casa (success quartet) and the reference
prototype's sage-green accent is explicitly rejected. A pinned card is **not** a
success state — it is a role-relevance signal, which is exactly what the single accent
exists for. Resolution: pinned Vault cards use the **Signal Blue Soft quartet**
(`#EAF1FB` badge fill, `#1E5FBF` badge text, `#C9D9F0` card border). The badge text
reads `PINNED FOR OWNER` / `PINNED FOR OPERATIONS`. Flagged explicitly so the checker
fails any green-pin implementation.

## Spacing Scale

The Casa system uses a 2px-grid with named tokens (`hair` 2 / `tight` 6 / `cozy` 10 /
`step` 14 / `page-inset` 22). Phase 1 **does not** replace it — preserved surfaces keep
their existing spacing. For the **new** surfaces (nav, Exception Board, Vault, Assistant)
this contract declares a 4-multiple scale so new layout is consistent and checker-legible.

| Token | Value | Usage on new surfaces |
|-------|-------|-----------------------|
| xs | 4px | Icon-to-label gaps, pill internal gap, badge padding |
| sm | 8px | Compact element spacing, chip-to-chip gap in filter row |
| md | 16px | Default element spacing; exception-card internal block gap; greeting eyebrow→headline |
| lg | 24px | Card padding (`p-6` per brief = 24px); gap between exception cards; Vault card padding |
| xl | 32px | Section spacing (`space-y-8` per brief = 32px); top-nav horizontal inset; Vault grid gap |
| 2xl | 48px | Greeting block → status pills; major vertical breaks on Exception Board |
| 3xl | 64px | Page top inset below the nav; Assistant column top padding |

Every token above is a multiple of 4. **There are no spacing-scale exceptions** —
nothing in the spacing scale breaks the 4-multiple rule.

**Spacing notes (not scale tokens):**
- Preserved surfaces (Pricing Agent detail, tables, existing sheets) keep their current `globals.css` spacing untouched — they use the legacy 2px-grid named tokens, not this scale.
- Touch targets: interactive controls on mobile ≥ 44px tall (status pills, filter chips, nav drawer rows). 44px is a WCAG/touch minimum, not a spacing-scale token. Existing `.btn-primary`/`.field` are already 44px.

**Layout constants (fixed dimensions — declared with their owning component in the Component Inventory, NOT spacing-scale tokens):**
- Top-nav height (70px) — see Component Inventory → `casa/top-nav.tsx`.
- Exception Board content width (1000px) — see Component Inventory → Exception card.
- Assistant column width (700px) — see Component Inventory → Assistant.
- Vault side-sheet width (~500px) — see Component Inventory → Side-sheet (Vault drill-down).

These are content/layout widths and one fixed bar height; they are deliberately kept out
of the spacing scale because they are not rhythm units. Their values (70 / 1000 / 700 /
500) are unchanged — only their *location* in this document moved, so the spacing scale
stays purely 4-multiple.

## Typography

Four declared tiers for the new surfaces. Weights: **2 only** — regular 400 and medium
500 (the existing Casa system never uses 600/700 in UI chrome; Inter is loaded with
300–700 but Phase 1 uses 400/500 only, matching DESIGN.md).

| Role | Family | Size | Weight | Line Height | Usage |
|------|--------|------|--------|-------------|-------|
| Display / Headline | Playfair Display | 40px | 400 | 1.1 | The one route headline — "Good {timeOfDay}, {firstName}." on Exception Board; "Admin Vault" on Vault landing. One per route (One Headline Per Route Rule). |
| Heading (card/section) | Playfair Display | 18px | 500 | 1.25 | Exception-card serif titles; Vault card titles; side-sheet headers; sub-page H2s; Assistant section labels. |
| Body (reading) | Inter | 15px | 400 | 1.55 | Exception-card narrative body (2–3 sentences); Assistant conversation text; Vault key/value detail prose. **New 15px tier** — see Resolved Tension 1. |
| Body (UI chrome) | Inter | 13px | 400 | 1.5 | Table cells, nav links, sheet metadata, button labels, property/neighborhood subtitles, source-attribution footer, status-pill counts. |

**Supporting type rules (binding, carried from DESIGN.md):**
- **Eyebrow** — Inter, 11px, weight 400, tracking 0.18em, uppercase, color `#8C8C8C`. Used for "OWNER VIEW" / "OPERATIONS VIEW" greeting eyebrow and Vault breadcrumb labels. (`.section-eyebrow` exists.)
- **Pill label** — Inter, 10.5px, weight 500, tracking 0.12em, uppercase. Used for category pills, status pills, the "PINNED FOR {ROLE}" badge.
- **Suggested block** — the `Suggested:` label is Inter 13px weight 500; the suggestion text is **italic** (the brief's "italic Suggested: block"). The block sits on a `#F7F7F6` (`softgray`) fill. Note: this is the *one* sanctioned italic body context for Phase 1 — DESIGN.md reserves italic for sidebar group labels, but the sidebar is deleted, so the italic-suggestion treatment does not collide with any surviving surface.
- **Mono** — SF Mono, 11.5px, `tabular-nums`. Booking IDs (`BK-2847`), timestamps, costs. (`.mono` exists.)
- **Tabular numerals** — every numeric (status-pill counts, KPI-style figures, costs, percentages) uses `font-variant-numeric: tabular-nums`.

**Note on the four-tier limit:** the eyebrow (11px), pill label (10.5px), and mono
(11.5px) sizes above are **pre-existing Casa system constants carried forward verbatim
from DESIGN.md** — they are not new sizes introduced by Phase 1 and do not count against
the Phase 1 four-tier typography limit. The four-tier table is the count of *Phase-1
type roles*; these three are inherited decorative/audit-metadata constants. The single
genuinely new size this phase introduces is the 15px reading body (Resolved Tension 1).

## Color

Casa is a monochrome ink-on-paper base with **one** saturated accent (Signal Blue) and a
print-shop status-quartet system. Phase 1 keeps this verbatim. The 60/30/10 split:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (~60%) | `#FAFAF7` route canvas + `#FFFFFF` cards | Route background is the off-white canvas (Resolved Tension 2). Cards, sheets, panels, nav bar, Assistant input bar all pure white `#FFFFFF`. |
| Secondary (~30%) | `#1A1A1A` ink text + `#E5E5E5` rules + `#737373`/`#8C8C8C` muted text + `#F7F7F6` soft fills | Body text `#1A1A1A`; all borders 1px `#E5E5E5`; secondary/subtitle text `#737373`; eyebrows `#8C8C8C`; hover + `Suggested:` block fills `#F7F7F6`. |
| Accent (~10%) | `#1E5FBF` Signal Blue | See reserved-for list below. ≤10% surface coverage (One Voice Rule). |
| Destructive | `#8A2B1F` (text), `#FBEBE8` fill, `#F0CFC9` border | Destructive-action affordances only — see *Copywriting → Destructive*. Never a general accent. |

**Accent (`#1E5FBF`) is reserved EXCLUSIVELY for:**
1. The active top-nav tab — 2px Casa-blue underline + darkened text. Inactive tabs `#737373`.
2. Primary action buttons on exception cards and side-sheets (`.btn-sm-primary` already ink-on-white; the *primary* visual emphasis sits with ink — but where the brief says "primary Casa blue," the primary CTA on Exception cards and the Assistant send button use the Casa-blue fill. See note below.)
3. The notification-bell badge (`.notif-badge` — already `#1E5FBF`).
4. The "PINNED FOR {ROLE}" Vault badge + pinned-card border (Resolved Tension 3 — `#EAF1FB`/`#1E5FBF`/`#C9D9F0` quartet).
5. The selected filter chip — NOTE: the existing `.filter-chip.active` is ink `#1A1A1A`. The brief says the selected "All" chip is "Casa blue bg, white text." Resolution: the *active* filter chip uses **Casa blue `#1E5FBF` fill, white text** (planner adds a `.filter-chip--accent` modifier or overrides `.filter-chip.active`). This is a deliberate, brief-mandated exception to the existing ink-active chip. **Contrast caveat:** white on `#1E5FBF` is ~4.7:1 at the chip's 10.5–12px label size — above the 4.5:1 AA floor but with little margin. The executor must verify white-on-`#1E5FBF` contrast with a contrast checker at implementation time; if the rendered chip falls below 4.5:1, bump the chip label to weight 500 (large-text 3:1 threshold does not apply at this size) or darken the fill toward `#134E8B`.
6. Side-sheet / "View all" / breadcrumb links and the Assistant suggested-prompt chip hover/active outline.
7. `:focus-visible` ring on primary CTAs (already wired — `rgba(30,95,191,0.55)`).
8. Text-selection highlight (`rgba(30,95,191,0.15)` — already wired).

**Primary-button color note:** The Casa system's default primary is ink `#1A1A1A`
(`.btn-sm-primary`). The brief explicitly says the Exception Board primary action button
and the Assistant send button are "Casa blue." Resolution for Phase 1: the **per-card
primary action** (e.g. "Approve Fix", "Call Cleaner") and the **Assistant send button**
use a Casa-blue fill (`#1E5FBF` bg, white text); the planner adds a `.btn-sm-accent`
class. Secondary actions stay `.btn-sm-outline`; tertiary "Dismiss"/"Resolve"/"Ignore"
is a plain ink-soft text link. This keeps blue coverage at one button per card — within
the One Voice budget — while honoring the brief.

**Status / urgency quartets (binding — Print-Shop Ink-Drawer Rule):** every status hue
ships as dot + text + soft-fill + border, applied as a set. Existing classes
`.pill-Critical/.pill-High/.pill-Medium/.pill-Low` and `.urg-*` are reused for the 4
**urgency** status pills.

### 8 Exception-Category color quartets (RECONCILED — supersedes the brief's raw palette)

The brief proposes a Tailwind-default `red-50/yellow-50/green-50/purple-50/orange-50`
palette for the 8 categories. That palette is **not adopted as-is** — it violates two
binding Casa rules: (a) Tailwind's default `green-500`/`purple-500` are saturated hues
Casa does not use, and the reference green is explicitly banned; (b) Casa status colors
must be print-shop quartets, not single Tailwind steps. Below is the reconciled,
WCAG-AA-checked mapping. Each category maps onto an existing Casa quartet wherever one
exists; two new quartets (Pipeline, Compliance) are added in the Casa idiom.

| Category | Maps to | Pill fill | Pill text | Border + dot + left-edge | Contrast (text on fill) |
|----------|---------|-----------|-----------|--------------------------|--------------------------|
| Guest | Critical quartet | `#FBEBE8` | `#8A2B1F` | `#C0392B` | ~7.0:1 — PASS |
| Cleaner | Critical quartet | `#FBEBE8` | `#8A2B1F` | `#C0392B` | ~7.0:1 — PASS |
| Pricing | Medium quartet | `#FAF4DD` | `#6F5A14` | `#C9A22B` | ~6.4:1 — PASS |
| Maintenance | High quartet | `#FBF1E4` | `#7A4A14` | `#D9822B` | ~6.6:1 — PASS |
| Owner | Signal Blue quartet | `#EAF1FB` | `#134E8B` (Signal Blue Deep — for AA on the soft-blue fill) | `#1E5FBF` | ~7.1:1 — PASS |
| Revenue | Signal Blue quartet | `#EAF1FB` | `#134E8B` | `#1E5FBF` | ~7.1:1 — PASS |
| Pipeline | NEW — Casa-idiom slate-teal | `#EAF0F0` | `#2A4A4A` | `#3E6F6F` | ~7.4:1 — PASS |
| Compliance | NEW — Casa-idiom muted plum | `#F1ECF2` | `#5A3A63` | `#7A5A82` | ~7.0:1 — PASS |

Notes for the planner:
- Guest and Cleaner intentionally share the Critical quartet — both are operational fires; the **category pill text label** ("GUEST" vs "CLEANER") disambiguates, and per the next bullet, color is never the sole signal.
- Owner and Revenue share the Signal Blue quartet (they are the owner-relevant, advisory categories). Text uses **Signal Blue Deep `#134E8B`**, not the brighter `#1E5FBF`, to clear 4.5:1 on the `#EAF1FB` fill. This is the same pattern the existing `.ch-BookingCom` pill already uses.
- Pipeline and Compliance get two **new** muted quartets in the Casa print-shop idiom (desaturated, ink-leaning). They are NOT Tailwind `green-500`/`purple-500`. The slate-teal is deliberately not the banned sage green — it is a cool desaturated neutral, ink-adjacent.
- The category's **left-border accent on the exception card** uses the quartet's dot/border color (the darker step). DESIGN.md bans a colored `border-left` > 1px *as a side-stripe border*. Resolution: render the category accent the same way `.kpi-card .kpi-rule` does — a 2px colored bar positioned **inside** the card border via an absolutely-positioned element, not as a `border-left` width. The planner must implement it as an inner rule, not a thick border. (Checker: flag any `border-left-width > 1px`.)
- The brief's "colored dot" on the card uses the same darker quartet step (8px dot, the existing `.urgency-dot` sizing).

**Color-is-never-alone (WCAG 2.1 AA — binding):** every category pill carries its
uppercase **text label**; every status pill carries its count + word; the urgency dot is
always paired with the urgency pill's word. No information is conveyed by color alone.

## Interaction & Motion Contract

- **Route entrance:** every page root `<div>` carries `.route-fade` (220ms opacity + 2px Y). Already wired.
- **Side-sheet entrance:** `.sheet` (280ms `cubic-bezier(0.2,0.7,0.2,1)`) + `.sheet-overlay` scrim `rgba(26,26,26,0.40)`. Already wired.
- **Mobile nav drawer:** slide-in via `transform: translateX()` only — no layout-property animation. Backdrop scrim same as sheet. ~240ms ease-out.
- **Status-pill count updates:** animate via opacity/transform only when counts change.
- **No bounce, no elastic.** Ease-out curves only. No CSS layout-property animations (`transform`/`opacity` only).
- **`prefers-reduced-motion: reduce`:** disables route-fade, sheet, drawer, toast, and card-hover transitions. Already wired in `globals.css` — the new drawer + status-pill animation must be added to that media block.
- **Assistant demo behavior:** clicking a prompt chip populates + sends the input → user bubble + loading indicator → canned response after a 1–2s delay (local timeout, no network).
- **Hover:** exception cards lift via `.ex-card:hover` (border darken + `0 14px 38px -22px` shadow). Vault cards use a `.prop-card`-style lift. No resting shadows (Flat-at-Rest Rule).

## Accessibility Contract (WCAG 2.1 AA — pragmatic, binding)

- **Contrast:** 4.5:1 body text / interactive labels; 3:1 large text (≥18pt or ≥14pt bold) and UI component boundaries. All 8 category quartets above are pre-checked ≥6:1. The Casa-blue active filter chip (white on `#1E5FBF`, ~4.7:1) must be re-verified at implementation time — see Color reserved-for item 5.
- **Color never alone:** every category pill, status pill, and urgency dot carries a text label. (Verified in the category table.)
- **Keyboard reachable:** top-nav tabs, user dropdown, notification bell, filter chips, exception action buttons, Vault cards, table rows, side-sheets, Assistant input + chips — all operable without a mouse.
- **Icon-only buttons:** the notification bell carries `aria-label="Notifications"` + `title`; any other icon-only control carries an `aria-label` + `title` (CLAUDE.md binding rule).
- **Focus:** `:focus-visible` 3px ring (ink-tinted default `rgba(26,26,26,0.18)`; Casa-blue `rgba(30,95,191,0.55)` on primary CTAs). Already wired — applies to new components automatically.
- **`prefers-reduced-motion`:** honored on every new animation (drawer, status-pill count, route fade).
- **Small type:** 10.5–11px eyebrows/pill labels are decorative metadata only — never the sole carrier of a critical value (counts also appear as the pill word).
- **Side-sheet ARIA** (`role="dialog"`, `aria-modal`, focus trap) is **deferred to v2** per STATE.md Deferred Items / V2-A11Y-01 — Phase 1 keeps the existing side-sheet pattern. Keyboard *reachability* (Esc-to-close, focusable controls) is still required this phase.
- **Mobile:** touch targets ≥44px (status pills, filter chips, drawer rows, action buttons).
