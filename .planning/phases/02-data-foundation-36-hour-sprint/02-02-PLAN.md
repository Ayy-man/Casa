## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Tampering/Information Disclosure | SQL injection surface in `src/lib/data/*` | mitigate | Every query uses the Supabase JS query builder's parameterized methods (`.eq()`, `.gte()`, `.select()`, `.single()`) — NO string-interpolated SQL, no `.rpc()` with raw SQL, no `supabase.sql` template strings. Filter args are passed as builder method arguments, which Supabase parameterizes. |
| T-02-06 | Information Disclosure | Anon-key-readable tables, no RLS | accept | Same accepted risk as Plan 01 T-02-01 — PROJECT.md defers RLS to v2 (single-tenant, shared demo creds). Not a blocker. |
| T-02-07 | Tampering | `as any` type widening masking row-shape drift | mitigate | D-10 forbids `as any`; the `<verify>` automation greps for it and fails the task if present. Rows are typed from generated `Database` types only. |
</threat_model>
